# SkyMessage на VPS

Ставится рядом с другими проектами на том же сервере и ничего у них не трогает:

- всё лежит в `~/skymessage` и работает как отдельный Docker Compose проект `skymessage`, со своей сетью
  `172.30.80.0/24`, своими томами и своей базой PostgreSQL;
- порты 80 и 443 сервера не используются (их держит другой проект за Cloudflare). Мессенджер доступен напрямую по
  `https://chat.skye.estate:8443`: запись в DNS без проксирования Cloudflare, потому что Cloudflare в России режут;
- наружу открыты только 8443 (HTTPS), 7881/tcp и 7882/udp (звонки). API, база и сигналинг LiveKit во внутренней сети;
- у контейнеров ограничены память и процессор, а FFmpeg обрабатывает по одному видео за раз;
- HTTPS-сертификат выпускает Caddy через DNS-проверку Cloudflare (токен с правом Zone → DNS → Edit лежит в
  `~/skymessage/cloudflare.env`).

## Обновление

```bash
deploy/vps/deploy.sh
```

Скрипт публикует API с веб-клиентом на этом компьютере, заливает файлы через rsync (только изменения) и
пересобирает лёгкий образ на сервере. Компиляции на сервере нет.

## Секреты и бэкапы

`~/skymessage/.env` создаётся при первом развёртывании (`init-env.sh`) и больше не меняется. **Сохрани его копию
в надёжном месте**: `STORAGE_MASTER_KEY` расшифровывает все фото, видео и файлы, без него бэкапы бесполезны.
Там же лежит код приглашения для регистрации (`REGISTRATION_CODE`).

Бэкап базы делается каждый день в 04:17 (crontab пользователя, `backup.sh`), хранятся три последних дампа в
`~/skymessage/backups`. Это копии на том же сервере: для настоящей защиты их стоит периодически скачивать.

## Откат


Остальные проекты на сервере это не затрагивает. Данные остаются в томах `skymessage_*`.
